gig workflow

从报价到交付的当前工作流

这份页面描述当前公开命令面：gig 只负责账本、状态机、校验、上传留痕；项目文件、计划页、验收材料和客户包内容由外部 workflow 或 agent 生成。

1. 状态主线

lead negotiating accepted plan_ready plan_approved in_progress ready_to_deliver delivered revision paid archived

返修后可以再次走客户包发送路径，订单会从 revision 回到 delivered。

2. 新订单与报价

gig quote new --slug crawler-a --title "数据爬虫" --project-type crawler --summary "采集公开列表并导出 CSV"
gig quote price crawler-a --min 3000 --recommended 5000 --max 8000
gig quote mark-sent crawler-a
gig quote accept crawler-a --project-dir ~/dev/partjobs/crawler-a

接受报价只登记外部 workflow 已经生成的项目路径，不生成项目文件。

3. 计划与验收

计划关

gig plan ready crawler-a

验收关

gig acceptance check crawler-a

验收材料由 workflow 写入项目目录；gig 只校验并推进状态。

4. 客户包交付

客户包目录由外部 workflow 准备；包 ID 由 JC 确认并原样成为文件名，不添加前缀：

.gig/delivery/2026-05-27/
  client/
  manifest.toml
  export/crawler-a-v1.zip
gig package check crawler-a \
  --delivery-date 2026-05-27 \
  --delivery-dir ~/dev/partjobs/crawler-a/.gig/delivery/2026-05-27 \
  --package-id crawler-a-v1

gig package send crawler-a \
  --delivery-date 2026-05-27 \
  --delivery-dir ~/dev/partjobs/crawler-a/.gig/delivery/2026-05-27 \
  --package-id crawler-a-v1

package send 只发送同一日期、路径及 ID 下已经校验的 ZIP；远端 basename 仍是 crawler-a-v1.zip。未传 --package-id 时兼容旧的 client-package.zip。

  • ID 长度为 1–64 个 ASCII 字符，首位是字母或数字，其余可用字母、数字、点、下划线和短横线；拒绝 ..、路径和 .zip 后缀。
  • manifest.toml 的 client_files 是非空、无重复的精确白名单。
  • 内部目录、隐藏路径、反斜杠路径、未声明 ZIP 条目、符号链接逃逸都会被拒绝；不依赖固定名称的 DELIVERY 文档。
  • 客户包发送是唯一正式客户交付路径。

5. 单独附件上传

gig artifact send crawler-a report.pdf screenshot.png

用于临时附件、补充材料或沟通文件。它会上传每个文件并写入 delivery_artifacts，但不改变订单状态。
